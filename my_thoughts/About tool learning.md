# About Tool Learning

## Glossary

* Tool - Any thing, physical or non-physical to help you get the job done. examples include:
  * English
  * visual studio code
  * Numpy
  * Taylor's Theorem

## Why I learn?

* [To get job done](./Get%20My%20Job%20Done.md).
* To get inspirations, eg. learn how the author tackles his problems.
* Exercise your brain, for example, learning *abstract algebra*, that will generate great long term value, I will not discuss this kind of objective here.

## A myth of tool learning

I opt to learn a tool as learn a curriculum, that means I opt to learn all details of the tool, after this whole process, I feel confident to use the tool. But that is not the case:

* You could get job **properly** done by just learning part of tool you needed.
* It's an illusion that I master the tool just by reading through the document, even when I type all the examples. I could only master
a tool by building something.
* Due to shortage of time, I'm very likely to lose the overall understanding of the tool and fail to master the key parts to current job.

## How to learn a tool wisely?

* Focus on the visible output
* Ask what are the minimum requirements to start to work?
* Give it a quick read through (breadth first search) and get a bird view, get the answer **how this tool could help you to get job done**?

In this step, **mind map** is a useful tool, note you may create a few key points in mind map.

* If you find something curious and want want to dig it more, don't dig it **immediately**, rather you should put it in memo, or mark it in mind map, it could be investigated in an appropriate time later.
